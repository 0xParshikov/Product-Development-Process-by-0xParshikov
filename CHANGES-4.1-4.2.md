# Изменения 4.1 → 4.2

16.11.2026. Причина: агент предложил отдельный адрес и стек для проверки простого обновления библиотеки, хотя у проекта есть Dev; основание — формулировка «изолированный кандидат в Dev». Согласовано владельцем, проверено куратором.

| № | Было | Стало |
| --- | --- | --- |
| 1 | До Rollout нельзя менять ни один контур | После «DoR согласован» существующий Dev проекта обновляется в границах работы как часть Delivery; если целевой контур — сам Dev, его обновление — Rollout. Обновления и проверки не удаляют и не переписывают реальные данные |
| 2 | Веб-сервис запускается изолированным кандидатом в Dev | Кандидат — одна зафиксированная версия приложения в существующем Dev по его адресу, не отдельный сайт, стек или копия данных. Dev занимает одна работа; отдельная среда — по обоснованной необходимости и решению владельца |
| 3 | Rollout не отделён от обновлений Dev | Rollout переносит проверенный артефакт в целевой контур (обычно Private) после положительного DoD и разрешения Rollout |
| 4 | Архитектура: кандидат размещается отдельным входом в Dev | Кандидат проверяется в существующем Dev проекта |
